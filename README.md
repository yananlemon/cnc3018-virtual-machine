# LUNYEE 3018 Pro Ultra Virtual Machine — 0.5

独立的 Windows x64 C++20 / Qt 6 Widgets / OpenGL 桌面仿真项目。提供独立的控制器内核、木料去除引擎、机械模型和可自定义装夹的桌面界面。

## 启动

解压便携 ZIP，保留 exe、DLL 和插件文件夹的相对位置，双击 `cnc3018_vm.exe`。需要 Windows x64 和支持 OpenGL 3.3 的显卡驱动。无需安装 Qt。

1. 选择“内部连接”，点击“连接”。
2. 点击 Home，等待状态从 Home 变为 Idle、基准变为“已回零”，机器 MPos=(0,0,-2)。XY零点在台面工作范围左上角；Z退让2mm。初始报警锁定是正常行为。
3. 载入 G-code，核对“加工设置”中的刀具、木板及零点。点击运行，观察真实木料去除；勾选“工件特写”放大成品。鼠标左键拖动旋转，滚轮缩放。
4. 粗加工后用“接续加工”加载精加工文件，保留当前木板和工件零点；仅更新刀具候选参数。
5. 用“导出雕刻 STL”保存当前真实表面；“恢复毛坯”才会清除雕刻。
6. “暂停”会减速并保留运动队列，“恢复”继续；“取消点动”减速后丢弃点动队列。
7. “停止发送”只停止发送器后续命令，已进入 RX/运动队列的命令仍执行；需要停止运动时使用暂停或 Reset。

“解锁”只解除报警，不移动、不建立回零基准。Reset 清空 RX、运动队列和内置发送器账本，保留实际机械位置并使基准失效。运动中 Reset 报 `ALARM:3`。断开只断开通信，内核继续执行已接收队列；重新连接可查询实际状态。

## 自定义装夹与视角

点击“木板 / 夹具 / 刀具”：木板可设置长宽厚、台面位置、程序原点，也可一键居中。勾选“保留我的木板设置”后，导入G-code保留木板尺寸和位置；新任务仍会建立毛坯，“接续加工”保留雕刻。夹具可设置0至4只，每只独立设置启用、X/Y、朝向、长度、宽度和压板底高；“随板厚”让压板贴合木板原始上表面。关闭自动布局后，夹具位置不会随导入文件改变。仅调整夹具不清除雕刻、不改变工件零点。

设置自动保存在exe旁的setup.json，下次启动恢复。也可在设置窗口保存/载入单独的装夹JSON；载入装夹建立新毛坯。刀具页可选择是否采用文件中的已识别刀具参数。

左键拖动旋转，右键拖动平移整个画面，滚轮缩放；右键平移在透视、旋转角度和正交俯视下均按屏幕方向移动。操作只改变视角，机器MPos/G92和木板保持不变。“复位视角”清除平移；工件特写下切换正面/背面/俯视按工件尺寸保持合适观看距离。详见 [v0.5 设置说明](docs/setup-v0.5.md)。

## 真实雕刻

平底刀、球头刀、V刀按实际执行的运动与主轴状态，连续扫掠木板高度场，生成槽底、侧壁与浮雕表面。支持中文注释、最大64MB文件、1/5/20/100/1000倍仿真速度。自动导入默认网格0.1mm，最多200万个高度采样；超过容量时自动调整网格间距并显示实际值。小件可在加工设置中使用0.05mm。文件注释只作为参数候选，不执行其中的文字指令。

暂停、Reset、重复运行、清除刀路不恢复毛坯。G92只改变坐标，木板保持装夹位置。Reset后需要重新Home；自动导入任务再次运行时会重新准备表面零点。仅换刀保留已有雕刻。STL含当前表面、底面和外侧壁，坐标轴与OpenGL一致（Y向上），单位mm。

详见 [v0.4 雕刻说明](docs/carving-v0.4.md)。

## 控制与通信功能

- 内部连接与 Windows COM 后端，双向字节通信、启动消息、115200 8N1。
- 实时字节 `?`、`!`、`~`、`0x18`、`0x85` 在行缓冲之前处理，无需换行且不产生普通 `ok`。
- `$J=` 点动、`$H` 回零、`$X` 解锁，以及 `$`、`$$`、`$G`、`$#`、`$I` 查询。
- 有界 RX（127 可用字节）、运动队列（15 段）、逐行确认、字节计数流式发送。
- 三轴速率约束、加减速、减速暂停/恢复、硬限位报警注入、软限位检查。
- `G0/G1`、`G2/G3` 的 G17 平面 I/J 圆弧（支持整圆与 Z 螺旋插补）、`G20/G21`、`G90/G91`、`G53`、`G54`、`G92/G92.1`、`G4 P秒`、`G94`、`M3/M5 S`、`M9`、`M2/M30`、N 行号。M4 反转明确报错。
- 未实现指令明确返回错误，包括 R 圆弧、G18/G19、G55–G59、G10、探测、刀具补偿、换刀、M0、M8、设置写入、`$C` 检查模式。没有刀仓、对刀块和换刀流程。
- 真正 OpenGL 3.3 核心网格、透视投影、深度缓冲、法线光照。机架、固定龙门、Y 台面、X/Z 滑座、主轴、夹头、刀具和工件按父子关系移动。
- 模型只读取控制器实际执行位置；“已发送/已确认”统计行，“已执行运动”统计已完成运动段，两者数量不要求相等。未确认字节数单独显示。刀路是已执行的刀尖轨迹，不是发送轨迹。

## 机型与坐标

本版以 LUNYEE 3018 Pro Ultra 官方照片和装配图重建。名义行程 X/Y/Z 为 300/180/80 mm，机器坐标分别为 `[0,300] / [0,180] / [-80,0]`。当前产品页标 Z80，官方旧装配手册标 Z78；界面明确标注使用 Z80 标称配置，不能作为实机限位标定值。500W / Ø52mm 主轴、HGH15 X 导轨、2040 X 型材、4040 Y 型材、六个限位及急停位置据官方资料，其他几何尺寸为照片估计。参数集中于 `src/core/lunyee_profile.h`，证据与待测尺寸见 [机型重建说明](docs/lunyee-model.md)。未找到制造商公开 STEP/CAD；本模型不声称达到 CAD 或装配公差精度。

采用用户指定的左上 XY0 仿真配置：X向右，Y向前/俯视向下，Z向上。Z向正端找开关、定位并退让到-2；XY向负端开关定位，最后向内退让2mm，停靠点定为机器XY0，完成位置 `(0,0,-2)`。这不是厂商默认固件设置；详细回零阶段、Jog边界及圆弧镜像说明见 [v0.3 坐标说明](docs/coordinates-v0.3.md)。仿真最大速度 1000/1000/400 mm/min，加速度 100/100/60 mm/s² 为保守默认值；官方 5000 mm/min 系统速度宣传值不能代替各轴实测设置。官方实机资料标 GRBL 1.1f，本程序保留自定义 1.1h 子集接口，并在启动消息中注明仿真身份。

`G54` 的持久偏置为零；`G92` 设置临时工件偏置，工作坐标 `WPos = MPos - WCO`。G92 与主轴/程序结束等同步指令等待此前队列完成后确认。所有正常运动仍在机器坐标中检查限位。Reset 清除 G92 偏置。

世界坐标采用 Y 向上。刀尖世界 X=`MPos.X-150`、高度=`MPos.Z+加工设置中的刀尖高度基准`（内置示例默认154，自动导入默认148）；台面世界 Z=`90-MPos.Y`。轨迹存于台面局部 `(MPos.X-150, MPos.Z+高度基准, MPos.Y-90)`。所以机器XY0对应有效工作范围左后角，X+向右、Y+使台面向后、刀具相对工件向前。台面边缘有10mm余量，较小的示例木板放在中央；木板加工零点可另用G92。GUI区分机器MPos与工件WPos，Home保留G92，G92不改变机器位置。

G2/G3保持数值角度（G2负角、G3正角）和I/J语义，未交换指令。Y向下的俯视镜像后，G2视觉逆时针、G3视觉顺时针；界面已明确标注。这是用户坐标配置，不应当作惯常右手CNC坐标系。俯视为正交投影，有实际三维原点/X/Y标识和工作范围边框。
台面顶面世界高度 70、木板厚 14、木板顶面 84，对应机器 Z=-70。Z 最低 -80 对应刀尖高度 74，保留 10 mm 工件内行程，并距台面 4 mm。此坐标零点是模拟装夹设置，不是厂商规定的机器零点。示例先用G53 G0定位到机器 X120/Y65/Z=-65（不受已有G92偏置影响）（表面上方 5 mm），用 `G92 Z5` 将木板表面定义为工作 Z0，再以工作 Z=-1/-2 作浅切，最终回到工作 Z5。绿色轨迹只记录主轴开启、实际执行且进入工件表面的刀尖位置；快速接近和抬刀不留下切削线。工件半透明开关便于检查表面下的轨迹；v0.4 独立材料引擎直接改变木板网格；不透明工件同样可见雕刻。

提供正面、背面、正交俯视快捷视角。机械模型包含有槽型材截面、薄金色侧板、真实通孔台面、单面网格刻线、HGH 导轨/滑块、螺旋丝杆、手轮、带 Ø52 通孔的金色夹座、冷却罩、ER11 外观、微动限位、后置控制板/电源和线缆。六个微动开关是可见零件，回零逻辑仍采用健康开关模型。急停按钮是模型外观；运动控制使用 GUI 的暂停/Reset。尚无点击三维按钮的交互。

## 外部 CNC sender 与虚拟 COM

应用打开已有 COM 端点，**不会创建虚拟串口**。外部 sender 与虚拟端口对联机尚未验证。

先安装和配置适合当前 Windows 的虚拟 null-modem 驱动，建立两个 COM 名称端点，例如 `COM10 ↔ COM11`。可评估 [com0com](https://com0com.sourceforge.net/) 或其他提供已签名驱动的端口对工具；驱动安装、系统兼容性和签名要求由所选驱动决定。当前交付不安装驱动，也不改变系统驱动/安全设置。

```text
外部 sender（COM10，115200 8N1，无流控）
    ↕ 虚拟 null-modem 端口对
虚拟机器（COM11，Windows COM 模式）
    ↕ Win32 OVERLAPPED 双向字节
独立控制器 → 实际位置 → OpenGL 机械模型
```

应用选择 Windows COM、COM11 并连接，然后 sender 打开 COM10。不要让两端程序打开同一个 COM 名称。为收到新的启动消息，sender 连接后发送 `Ctrl-X / 0x18`；应用打开端口时也发送 banner。此版不模拟 Arduino DTR 电平触发的复位。

sender 可先发送 `?` 查询 Alarm，发送 `$H\n` 等待回零结束后的 `ok`，再发送程序。`$X\n` 只解锁。先用逐行发送/等待 `ok` 或 `error:x` 的方式联调；字符计数方式不得超过 127 个未确认字节，单行规范化后最多 79 字符。遇到 `ALARM` 或 Reset/banner 必须停止流并重置 sender 的未确认账本。COM 模式下 GUI 普通行命令禁用，由外部 sender 独占行确认序列；GUI 可控制实时命令、查看执行状态和注入限位报警。

连接不成功时日志显示 Windows 错误码；常见原因包括端口名不存在或被占用。双方必须支持完整 8-bit 传输，不能把 `0x85` 发送成字符串“0x85”。

## 与原版 GRBL / grblHAL 的差异

这是自定义仿真内核，不是原版 GRBL 固件或 grblHAL 运行时，不宣传全 GRBL 兼容。

- 每个运动段按零入口/零出口速度运行；没有 GRBL 的前瞻、拐角速度和 junction deviation 规划，连续短线会逐段停稳。圆弧在单个队列块内连续插补，速率采用保守的轴/向心加速度约束。
- 回零是预设健康限位开关的 Z→XY、快速寻找→退回→慢速定位→退回流程。没有开关线路/抖动/缺失/卡住、回零超时等故障建模，也没有宣称这些故障经过验证。界面“限位故障”是独立硬限位报警注入。
- 时间由桌面计时器驱动，2 ms 逻辑积分步长；单次 GUI 停顿最多推进 50 ms，长停顿时模拟时间会落后现实时间。不模拟微控制器步进脉冲、电机失步、机械柔性。
- RX 超限产生可见报警并要求复位，采用仿真器保护行为，非原版 AVR 静默丢字节行为。
- 每个 `?` 立即响应，回零时忽略；没有硬件中断的查询合并。此版不模拟扩展倍率覆盖、门输入、EEPROM 保存、启动行和所有系统设置。
- 断开不自动取消运动。重新连接会发启动 banner，但不会自动复位内核；使用 Ctrl-X 明确复位。Reset 后重新锁定并使基准失效，是本版保守策略。
- 只有 G54 零持久偏置 + G92 临时偏置；`$#` 中 G55–G59 的零值为固定未使用存储，选择相应坐标系仍报错。主轴以状态变量模拟，暂无主轴旋转动画或切削力/木纤维破坏计算；已实现真实几何材料去除和刀具与木板接触诊断。
- 参数不持久化。C++ 输入有数值范围保护，绝对值超过 1e9（单位换算后的坐标和进给也检查）返回错误。

协议参考：[原版 GRBL 1.1 Interface](https://github.com/gnea/grbl/wiki/Grbl-v1.1-Interface)、[Commands](https://github.com/gnea/grbl/wiki/Grbl-v1.1-Commands)、[Jogging](https://github.com/gnea/grbl/wiki/Grbl-v1.1-Jogging)。[grblHAL Simulator](https://github.com/grblHAL/Simulator) 官方标为实验性质；可后续作为独立适配器评估，其协议和内核行为不得直接等同于原版 GRBL。此版未复用其代码。

## 构建与测试

本机实际工具链：Windows x64、MSYS2 MinGW64 GCC 16.1.0、Qt 6.11.1、CMake 4.3.3。需要 Widgets、OpenGLWidgets、OpenGL；无需 Qt SerialPort，串口用 Windows API。预设路径适用于本机，可在其他机器修改工具链路径或以 `-DCMAKE_PREFIX_PATH` 指定 Qt。

```powershell
cmake --preset windows-release
cmake --build --preset windows-release
ctest --preset windows-release
```

内核不依赖 Qt，`CNC_BUILD_DESKTOP=OFF` 可单独构建。源码三层 target：`cnc_controller`、`cnc_transport`、`cnc3018_vm`。C++20、禁用编译器扩展，GCC 使用 `-Wall -Wextra -Wpedantic -Werror`。串口 RAII 管理句柄与 OVERLAPPED 生命周期，GPU 资源在有效上下文中释放。UI、内核、串口由同一 GUI 线程独占；串口轮询不等待 I/O 完成，关闭时等待取消完成后才释放缓冲。以后迁移线程必须使用消息/快照，不能共享可变控制器状态。

11项 CTest 覆盖协议与实时命令、队列/确认/实际执行、暂停恢复、Jog 模态隔离、Home/Reset/限位、工作坐标与圆弧/螺旋、发送器信用与停止/Reset、大数和无效输入、串口名称验证与关闭状态 RAII 生命周期，以及非退化网格、真实孔洞、夹座孔、非正方形孔单元完整面积与圆角端点处理，以及左上原点、八阶段健康开关回零、退让基准、正负点动及镜像圆弧。串口测试不打开硬件端口，也不能代替外部端口对联机测试。

```powershell
./cnc3018_vm.exe --smoke-test C:/path/to/verification
```

自检推进示例至完整结束（模拟时间上限 600 秒），要求全部命令已发送且确认、无发送错误、Idle、RX/运动队列为空、OpenGL 初始化和截图成功，同时核对Home=(0,0,-2)、开关释放和9条Jog；生成 `home-gui.png`、`home-top.png`、`jog-positive-gui.png`、`gui.png`、`smoke.json`、正面/左前/背面/俯视及 Z 上下限检查截图（最后两张只设置视图快照，不移动控制器），成功退出码 0。外部 COM 验证字段固定为 false，直到真正安装端口对并单独完成联调。

便携打包脚本为 `scripts/package.ps1`，运行 windeployqt 并递归检查 PE 导入，补齐 MinGW 和 Qt 的非系统运行库。包内 `third-party-licenses` 保存所部署依赖的许可证，Qt 以可替换的动态库分发。
